## 目标与背景

基于 034 的 Rust `.pa` 解析内核实现变量域，将人可读的源文件转换为运行时快照，并支持语义往返存储和定位诊断。语言和主题域复用同一文件头、词法、版本与诊断边界；各域的 schema 由 022、030 扩展。当前仅规划，未实施。

## 范围与非目标

包含变量域的基础值类型、资源引用、受限算术、依赖求值、原子提交和文件保存；公共 `.pa` 文件头、YAML 风格缩进、无引号标量和诊断由 034 提供。不包含循环、脚本函数、跨文件 import、物理单位或字节码 VM。`kind language` 的 message 语义由 022 定义，`kind theme` 的键映射由 030 定义。

变量求值与工程会话解耦：025 交付通用值/诊断输出，022 和 030 通过 034 复用解析器处理语言与主题数据。语言 fallback、占位符校验、主题 schema、颜色校验和 UI 切换不扩入 025。

## 前置条件与待决策

024 的值与快照契约稳定；冻结 V1 文法、数值提升与上限，决定解析器实现方式并按依赖规则评估；不预先选择未经验证的新依赖。

## 实施步骤

1. 编写最小语法规格、正反例和诊断 code，明确无量纲与规范化输出语义。
2. 基于 034 的 AST 实现变量类型/引用检查、环检测与有限求值，输出快照及源位置诊断。
3. 接入运行时原子提交和文件读写，C++ ViewModel 仅暴露加载结果；验证失败保持原文件/快照。

## 预计改动

规划 Rust DSL 模块、小型 tests 夹具、文法说明及 bridge DTO；不保存 AST 到外部求解器协议。 上述新增路径/类型均为规划，以实施时实际模块归属为准。

## 验收标准

- [ ] bool/int/real/string/resource、前向引用与表达式按规则求值，重复声明和未知变量报告准确源范围。
- [ ] 循环依赖、类型错误、溢出、除零、NaN/Infinity、未知版本被拒绝；输入/深度/操作量上限有效。
- [ ] 解析/校验/写入失败均保留旧快照或旧文件；旧 revision 不能覆盖新数据。
- [ ] 保存后重载语义一致，类型和表达式不丢失；改变 UI 语言不改变文法、数字或值。
- [ ] 解析器可脱离工程会话返回值快照与诊断，工程提交由单独调用方负责，为 030 主题作用域复用提供边界。
- [ ] 变量域消费 034 的 `.pa` 文件头、UTF-8 和诊断规则，语言/主题域可在不复制 lexer 的前提下扩展声明。
- [ ] DSL 不能执行 shell/网络或绕过资源根限制，诊断以 code 与参数跨 FFI。
- [ ] 代码、测试、配置和文档一致，删除废弃实现；记录真实验证并同步索引。
