## 目标与背景

将 Theme token 映射到自制 DSL 配置，通过独立应用主题服务与 C++ ViewModel 驱动 QML 组件切换。主题选择仅在本次运行期有效；跨重启保存主题 ID、窗口状态等用户偏好由 125 的设置服务负责，避免本任务另建一套持久化。

## 范围与非目标

包含内置完整 GUI 默认快照、主题覆盖 schema、至少两套可选择主题、运行期切换和失败回退；不含主题编辑器、动画切换、用户偏好持久化、QML 代码注入或引擎重载。启动时恢复主题选择由 125 负责。

## 前置条件与实施步骤

上述依赖产物可用后实施；029 无需等待正式模块迁移 026，030 无需等待热重载 027。涉及 FFI 时沿用 025 已落地的契约。

先冻结键/类型/范围与 QML 属性映射。公共文法、解析器和源码诊断复用 034 的 `panta-dsl-core`；025 提供变量类型、求值与快照语义，030 负责主题 schema 与 QML 属性映射。完整默认值进入 `kind: variables` 的 `qml/Themes/gui-default.pa`；主题覆盖文件可稀疏声明 schema 中任意颜色、尺寸、字号或其他视觉 token，未声明项继承默认快照，不按类别限制可覆盖范围。单一 Rust schema 显式维护每个 token 的 DSL 键、类型、范围与 QML 属性名，保证扩展时映射明确且类型安全；ThemeViewModel 发布合并后的完整快照。应用服务在初始化时校验并缓存内置快照，切换只发布已校验快照；跨重启保存所选主题 ID 与启动恢复由 125 负责，不在 030 中直接写 QSettings 或另建持久化实现。
