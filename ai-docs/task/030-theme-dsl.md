将 Theme token 映射到自制 DSL 配置，通过独立应用主题服务与 C++ ViewModel 驱动 QML 组件切换。当前仍未实施；本次先冻结分层和边界，避免把未消费的 `.pa` 文件提前加入仓库。

## 范围与非目标

包含内置默认主题、覆盖 schema、至少两套可选择主题、启动恢复和失败回退；不含主题编辑器、动画切换、QML 代码注入或引擎重载。

## 前置条件与实施步骤

上述依赖产物可用后实施；029 无需等待正式模块迁移 026，030 无需等待热重载 027。涉及 FFI 时沿用 025 已落地的契约。

先冻结键/类型/范围与 QML 属性映射，复用 025 无工程依赖的解析器。默认 GUI 尺寸进入 `kind: variables` 的 `gui.pa`，主题颜色和可覆盖 token 进入 `kind: theme` 的 `light.pa`/`dark.pa`；合并后的完整快照由 C++ ThemeViewModel 发布给 Theme.qml。实现 GUI 线程发布、主题选择及偏好保存。

## 预计改动

现存 qml/、Theme.qml 及相关 CMake 文件；实施时新增 `resources/themes/` 下实际被构建和测试消费的 `.pa` 文件、主题服务与测试，不创建只登记不消费的空占位资源。

## 清理与兼容例外

同步清理被替换的控件、样式、默认值与调用点。无兼容例外，不长期保留双数据源或两套主题入口。

## 验收标准

- [ ] 未打开工程也可切换两套主题，组件颜色与尺寸同步更新，不重建 QML 引擎、不改变工程 dirty。
- [ ] 默认主题 DSL 完整；覆盖缺省键继承默认值，未知键/类型错误/非法颜色/尺寸越界拒绝整个候选。
- [ ] Theme.qml 为唯一 QML token 入口，默认值不在 QML 与 DSL 重复维护，键映射具有单一 schema。
- [ ] GUI 尺寸基线与主题覆盖分层；运行时原生 surface 几何不进入 `.pa` 或 Rust 热路径。
- [ ] 快速连续选择拒绝迟到结果，解析失败保留旧主题及偏好；偏好写入失败有明确诊断。
- [ ] 重启恢复有效主题，用户配置缺失/损坏时回退内置主题并保留原文件；高 DPI/字体/尺寸变化无布局回归。
- [ ] 代码、资源、测试、文档及索引一致，验证记录完整。
