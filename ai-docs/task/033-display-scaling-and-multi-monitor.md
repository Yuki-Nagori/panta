## 目标与背景

建立 QML、Qt Quick、VTK 视口和窗口持久化共同遵守的逻辑像素/物理像素边界，支持窗口跨显示屏和系统缩放变化而保持布局、渲染、输入和工程状态一致。当前仅规划，未实施。

## 范围与非目标

包含显示快照服务、DPR 与 viewport 转换、窗口状态恢复、多屏迁移、测试夹具和三平台真实窗口验收记录；不包含工程几何单位、VTK 渲染算法、桌面环境定制或远程桌面协议适配。

## 前置条件与待决策

005 的 Qt Quick 外壳和 007 的 VTK viewport 契约可用；实施前核实 Qt 6.11.2 对目标平台的 screenChanged、DPI 和窗口 framebuffer 行为，并固定舍入策略。显示 ID 的平台字段可用性和 Linux fractional scaling 的真实表现需在目标环境记录，不能凭单一开发机假设。

## 实施步骤

1. 定义显示快照、窗口状态和逻辑到像素转换的 C++ 契约，固定事件合并与发布时序。
2. 接入 QML Theme、窗口恢复和 VTK viewport；将输入拾取转换集中到渲染边界。
3. 增加注入式 DPR/多屏测试，完成 macOS、Windows、Linux 的真实窗口矩阵并记录未覆盖项。

## 预计改动

规划新增 `native/bridge/` 显示服务与测试、`native/render/` viewport 边界以及窗口设置迁移；具体路径以实施时现有模块归属为准。可能更新 `qml/Themes/Theme.qml`、应用入口和部署/验证文档，不改变工程文件格式或求解器协议。

删除散落的 DPR 乘法、整数比例缓存和按屏幕下标持久化的旧实现；若当前没有这些实现则记录无废弃项。默认无兼容例外。

## 验收标准

- [ ] QML/窗口只使用逻辑像素；逻辑尺寸到 framebuffer 像素只在渲染边界按当前 DPR 转换一次，覆盖 1.0/1.25/1.5/2.0。
- [ ] 窗口跨屏、DPR 改变、屏幕断开和睡眠恢复不重建 QML 引擎，不丢失相机、选择集、网格或任务状态。
- [ ] 窗口恢复按显示 ID、availableGeometry、最小尺寸和最大化顺序执行，目标屏幕缺失时可回退主屏幕且不产生不可交互窗口。
- [ ] VTK viewport、截图/离屏渲染和鼠标拾取使用明确的窗口 DPR/导出 DPR，不能读取主屏幕全局值。
- [ ] 自动测试和三平台真实窗口证据覆盖主要失败路径；未覆盖的 GPU/多屏场景明确记录，不能以 offscreen 代替。
- [ ] 代码、测试、配置、文档和 task 一致，删除旧转换路径，无未登记兼容分支。

## 风险与回退

平台 DPI 事件顺序或屏幕 ID 不稳定可能造成恢复位置错误或 framebuffer 短暂失配。所有更新先生成完整快照，失败保留上一份窗口/渲染状态；无法匹配显示时回退主屏幕可用工作区，不改工程数据。

## 决策与工作记录

- 2026-09-16：创建任务；底层统一使用 Qt 逻辑像素，DPR 只在渲染/导出边界转换。
