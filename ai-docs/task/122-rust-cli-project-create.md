## 目标与背景

为脚本和自动化提供可重复创建 `.panta` 工程的入口，并复用 GUI 已有的 Rust 工程创建规则。CLI 不自行实现名称、目录、覆盖保护或工程清单写入逻辑。

## 必读

- [应用命令层](../architecture/command-layer.md)

## 范围与非目标

- 增加一个 CLI 工程创建操作，参数至少能表达父目录与工程名，并输出创建结果。
- 复用 Rust 应用服务；GUI 与 CLI 对无效名称、目标已存在、目录不可写等条件保持一致。
- 为成功与失败路径增加 CLI 单元和真实子进程测试；目录不可用场景使用可移植的文件占用父路径夹具，不依赖宿主权限配置。

非目标：项目模板系统、GUI 对话框替换、覆盖已有项目、批量工程生成格式。

## 前置条件与待决策

- 依赖任务 121 合并并确认 CLI crate 与共享命令边界稳定。
- 复用 `ProjectService::create` 创建不存在的父目录与多级目录的现有行为；若今后调整，GUI 与 CLI 必须一致。不得默认为覆盖现有工程。

## 验收标准

- [x] CLI 与 GUI 共用同一 Rust 创建应用入口和校验规则。
- [x] 成功创建的工程可由 `project inspect` 重新读取；已有目标与无效输入返回非零退出码及可诊断错误。
- [x] 测试覆盖成功、目标冲突、无效名称及目录不可用；任务记录适用验证和独立评审结果。

## 风险与回退

避免覆盖已有目录或静默改变创建服务的事务行为。若 CLI 参数设计不能清晰映射现有服务，先收敛应用命令输入，不在 CLI adapter 复制校验。
