# 应用平台、Rust 与工程存储

[架构总览](README.md)

## Rust 的职责

Rust 负责工程、工作区、命令、任务、作业、序列化、撤销/重做模型及求解器客户端。插件体系是长期方向，V1 不要求先实现插件加载平台。C++ 负责 Qt 桥接以及几何、网格和渲染的 native 实现。

应用服务将用户命令转换为跨模块操作；Rust 与 C++ 之间优先传递明确所有权的 DTO、句柄和结果。FFI 优先验证 [CXX](../standards/cxx.md)，尚未完成集成；实施时定义字符串编码、缓冲区归属、释放接口、线程约束和错误映射；异常与 panic 不得未经处理跨越 FFI 边界。

## 工程模型

工程应组织元数据、几何资产、网格、材料、Studies、作业记录与结果引用。每个实体具有工程内稳定 ID，派生实体记录来源修订。模型状态与窗口布局、临时选中项等会话状态分开存储。

工程 dirty 状态来自已接受的领域变更。视口旋转是否持久化可以单独定义，不能让每一帧渲染都产生工程命令。Study 和 Job 区分：Study 是可编辑配置，Job 是某次固定输入快照的执行记录。

## 命令、任务与作业

命令表示可验证的用户操作，任务表示执行过程，作业表示求解运行。任务有 ID、状态、进度、取消请求和错误；开始后使用输入快照，防止执行期间读取到不断变化的工程。

撤销/重做适合工程模型变更。大型资产可以保存引用或修订，避免每步复制整个网格。外部求解进程已执行的计算不能靠撤销命令“倒退”；撤销只能调整本地配置或引用，取消作业是独立操作。

## 存储契约

具体容器、文件扩展名和二进制格式未定。逻辑上分为小型工程清单和大型数据资产：清单保存 schema 版本、实体关系、参数和资产位置；几何、网格、结果保存为可独立校验和按需读取的数据。

需要明确嵌入资产与外部引用策略。便携工程应包含必要资产或可解析的相对引用；只保存开发机绝对路径不能作为默认可移交方案。读取时对缺失资产、未知 schema 版本、损坏数据及单位不一致提供明确诊断。

保存采用临时写入、完整性检查和提交步骤，使失败不会损坏上一份有效工程。多文件工程需要整体提交或可恢复机制，单个文件原子替换不等于整个工程事务完成。不预先实现多版本 reader 或自动迁移；遇到不支持的格式版本明确拒绝并保留原始数据。确有现实迁移需求时单独建 task，遵循 [兼容例外规范](../standards/code-lifecycle.md)，迁移过程保留原始文件或可恢复副本。

## 大数据与缓存

结果按时间步、区域或字段延迟读取，缓存有容量与失效策略。缓存可重建，不能作为唯一数据源。关闭工程时取消读取、释放映射和资源；结果文件仍在写入时，仅开放已经正式发布的完整片段。

验收重点是保存/重开后 ID 与引用一致、资产缺失可解释、写入失败保留旧工程，以及旧任务不能污染新打开的工程。
