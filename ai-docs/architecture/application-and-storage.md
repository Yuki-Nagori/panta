# 应用平台、Rust 与工程存储

[架构总览](README.md)

路径、运行时上下文和变量输入的分阶段规划见[路径与运行时](../modules/paths-and-runtime.md)、[变量 DSL](../modules/variable-dsl.md)。这些基础不要求先实现完整虚拟机。

## Rust 的职责

Rust 负责工程、工作区、命令、任务、作业、序列化、撤销/重做模型及求解器客户端。插件体系是长期方向，V1 不要求先实现插件加载平台。C++ 负责 Qt 桥接以及几何、网格和渲染的 native 实现。

用户设置另见[048 设置服务与 Qt 持久化适配](../task/048-settings-service-and-qt-adapter.md)：Rust 负责设置 schema、默认值、范围和业务校验，C++ 负责 `QSettings` 的平台存取适配。`QSettings` 不进入 `panta-core`，QML 也不直接访问它；主题定义仍由 `.pa` resource 提供，设置只保存主题 ID、窗口状态等偏好。

应用服务将用户命令转换为跨模块操作；Rust 与 C++ 之间优先传递明确所有权的 DTO、句柄和结果。任务 057 已用 [CXX](../standards/cxx.md) 落地最小 `ProjectService`：创建、打开、保存和重命名命令通过 `ProjectSnapshot` 传递，错误使用稳定 `project.*` 代码。字符串编码、缓冲区归属、释放接口、线程约束和错误映射必须明确，异常与 panic 不得未经处理跨越 FFI 边界；大工程操作仍需异步化。

107 将工程模块组织为 model（命令 / 状态 / 清单）、error（稳定诊断）、mesh_cache（驻留策略）和 service（会话编排），公共 `panta_core::project` 门面及 CXX 入口保持原路径。方案配置和导入仍由应用服务校验及提交；具体持久化和后台执行契约继续按对应任务推进。

工程 revision 是过期请求的相关性键，递增通过单一检查入口完成。达到 `u64::MAX` 后拒绝需要新修订的变更，在修改内存、写入资产或启动候选提交之前返回 `project.command_invalid`；读取和无操作请求保持原语义。不能以饱和成功让不同工程状态共享同一修订。

## 工程模型

工程应组织元数据、几何资产、网格、材料、Studies、作业记录与结果引用。每个实体具有工程内稳定 ID，派生实体记录来源修订。模型状态与窗口布局、临时选中项等会话状态分开存储。

工程 dirty 状态来自已接受的领域变更。视口旋转是否持久化可以单独定义，不能让每一帧渲染都产生工程命令。Study 和 Job 区分：Study 是可编辑配置，Job 是某次固定输入快照的执行记录。

## 命令、任务与作业

命令表示可验证的用户操作，任务表示执行过程，作业表示求解运行。任务有 ID、状态、进度、取消请求和错误；开始后使用输入快照，防止执行期间读取到不断变化的工程。

`panta-core::task` 已有最小生命周期与协作取消（008）；真实异步导入的 [FSM 状态机方案](../modules/fsm.md) 仍为规划，由 [073](../task/073-fsm-dsl-and-import-state-machine.md) 跟踪。FSM 只在构建期声明结构，Rust 实现业务行为。导入准备归 `panta-import`，工程事务与通用任务生命周期留在 `panta-core`；准备完成不等于任务成功，工程发布成功后才能进入 `Committed` 并报告完整导入成功。取消 / 提交裁决、迟到结果与关闭后失效必须由 Rust 处理，Qt 仅消费展示快照。

[109](../task/109-bounded-background-execution.md) 将预检、只读激活、元数据提交及模拟任务接入私有有界执行模块。读取（预检 / 激活共享）最多 2 个 worker / 64 个在途作业，写入 1 / 32，模拟任务 2 / 64；在途数量包含排队与执行，满载立即拒绝，不阻塞宿主。排队只保存输入路径或已冻结候选，文件读取 / 解析从 worker 开始；领域取消与 FSM 仍由消费者裁决。空闲 worker 退出，不积累已结束的线程句柄。激活的在飞记录与未消费结果合计上限 256；模拟任务记录上限 256，drain 后回收终态，日志仍为 256 条环。这些是数量上限，不是单文件或全部结果负载的字节上限。

工程服务销毁时取消预检并使旧激活代次失效，释放旧结果；模拟管理器关闭领域状态并协作停止，不在 UI 交互线程 join。已接受的清单写入由后台持有候选和事务结果，宿主销毁只停止投递，未能交付的提交错误仍写入 stderr。原生入口在事件循环退出且 QML 引擎销毁后调用 Rust `finish_background_writes`：关闭后台写入准入并等待已接受作业完成，再退出进程。C++ 只安排生命周期调用，不决定提交或取消。正常退出收尾不等于异常进程终止 / 断电持久性保证。

撤销/重做适合工程模型变更。大型资产可以保存引用或修订，避免每步复制整个网格。外部求解进程已执行的计算不能靠撤销命令“倒退”；撤销只能调整本地配置或引用，取消作业是独立操作。

## 存储契约

完整工程容器和二进制资产格式仍未定。任务 057 的最小契约使用 `Documents/panta/<name>/<name>.panta` 目录包；任务 063 将主文件 schema 扩展为 `2`，在名称和修订号之外保存可重放的 STL `imports` 记录，记录固定导入记录版本与 STL 解析器版本，原始 STL 复制到 `assets/imports/`。打开仍接受 schema 1 并按缺省空 imports 读取，成功保存时写当前 schema；保存先在工程目录内写独立临时文件再替换主文件。该实现是当前边界，不代表完整工程格式，也不等于持久化了解析后的 Mesh IR。

[108](../task/108-project-write-coordination.md) 将工程写入集中到 Rust repository 租约：使用 fs4 同步文件锁协调同一工程的跨实例 / 跨进程写入；争用立即返回 `project.command_invalid`（`project write pending`）。锁文件 `<name>.panta.lock` 保持稳定，不在释放租约时删除。内存状态分别记录当前 revision 与已保存 revision；租约取得和清单替换前复核磁盘已保存修订，过期服务返回 `project changed on disk` 并保留其候选及旧磁盘内容。该锁为协作式，不拦截绕过租约的外部写入。

临时清单位于 `<name>.panta.write/`，按进程 ID / 序号使用 `create_new` 独立创建，碰撞有限重试；失败清理只针对当前租约拥有的临时文件。写入与 `sync_all` 成功后 rename 为提交点，其后只更新内存已保存修订。STL 资产复制、清单提交与失败回滚共享同一租约。稳定锁文件及空 staging 目录保留在工程目录，不写入清单或作为资产展示；本实现保证文件内容同步，不承诺所有平台断电后的目录项持久性。

[092](../task/092-plan-analysis-sequence-and-mesh-settings.md) 在当前清单中增加按导入记录 ID 索引的 `analysis_sequences` 稀疏覆盖表；缺省表示 Fill，非默认选择由 Rust 校验并事务保存。读取时拒绝未知序列或没有对应导入记录的覆盖项。`imports[].mesh_type` 保留 STL 导入时选择的类型，供 Tasks 展示；它不代表已经生成对应分析网格。当前暂以导入记录关联方案设置，后续独立 Study 模型应保持领域 ID 和修订边界。

目标存储将 `.panta` 保持为元数据和资产索引，规范 `SurfaceMesh` / 体 Mesh payload 旁置于同一可移交工程目录。索引按稳定 asset ID 和 revision 指向带格式版本、单位、来源 revision、内容摘要及相对路径的资产文件；打开工程只读索引，视口页签打开时由 Rust `panta-mesh` 按需读取并验证单个 Mesh。运行期缓存保存拥有内存的领域快照，C++ 通过批量 CXX DTO 创建 VTK 数据；VTK mapper、filter、actor 和 GPU 资源不写入工程。当前 `SurfaceMesh` 的三角面 payload 约 72 字节 / 面，binary STL 约 50 字节 / 面；若两者同时保留，Mesh sidecar 可能增加磁盘占用，不能预设其会压缩或减少显示内存。实现跟踪于 [088](../task/088-mesh-asset-sidecar-storage.md)，格式、原 STL 留存策略和事务细节尚待测量与决策。

资产文件使用不可变 revision 名称。保存时先写临时 sidecar、校验并发布文件，再原子提交引用它的新 `.panta`；崩溃产生的未引用文件不影响上个有效索引，后续清理也必须检查运行中任务和资产引用。相对路径使整个工程目录可移动。单文件原子替换不代表多文件事务；资产发布顺序、摘要校验和失败恢复须由实际实现测试。

需要明确嵌入资产与外部引用策略。便携工程应包含必要资产或可解析的相对引用；只保存开发机绝对路径不能作为默认可移交方案。读取时对缺失资产、未知 schema 版本、损坏数据及单位不一致提供明确诊断。

保存采用临时写入、完整性检查和提交步骤，使失败不会损坏上一份有效工程。多文件工程需要整体提交或可恢复机制，单个文件原子替换不等于整个工程事务完成。不预先实现多版本 reader 或自动迁移；遇到不支持的格式版本明确拒绝并保留原始数据。确有现实迁移需求时单独建 task，遵循 [兼容例外规范](../standards/code-lifecycle.md)，迁移过程保留原始文件或可恢复副本。

## 大数据与缓存

Mesh、结果按用户打开的页签、时间步、区域或字段延迟读取，缓存有容量与失效策略。缓存可由已提交资产重建，不能作为唯一数据源。关闭页签释放该页签独占的 CPU Mesh 快照和 VTK 显示对象；关闭工程时取消读取、释放映射和资源。结果文件仍在写入时，仅开放已经正式发布的完整片段。Mesh 快照容量和逐出阈值由 080 / 088 的代表性测量确定，不由 GPU RSS 单项推导。

验收重点是保存/重开后 ID 与引用一致、资产缺失可解释、写入失败保留旧工程，以及旧任务不能污染新打开的工程。
