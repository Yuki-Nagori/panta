# 材料、Study 配置与自动化

[架构总览](README.md)

## Study 的作用

Study 将网格、材料、工艺条件、边界条件和求解选项组织成一次分析的可编辑配置。平台负责配置表达、引用完整性和通用校验；物理方程、材料本构计算和数值求解属于[外部 MoldSolver](external-moldsolver.md)。

V1 可先提供求解器占位和可保存的 Study，不要求真实计算。界面必须清楚区分“配置完成”“尚未连接求解器”和“计算完成”，不能因显示了合成结果就标记分析成功。

## 配置模型

Study 引用明确的网格版本，材料分配绑定区域 ID，边界条件绑定面/边或网格分组。值包含单位或明确的统一单位约定。材料数据携带来源和版本，避免同名材料更新后静默改变已提交作业的输入。

具体 Filling/Flow/Thermal 参数由支持的求解器能力决定，不在 UI 中硬编码唯一物理模型。平台可先提供名称、引用、参数分组和错误展示的通用骨架；正式参数 schema 由协议与求解器共同确定。

规划由 `panta-material` 管材料定义与版本，`panta-bc` 管边界条件和目标引用；Study 应用模型拥有材料分配与分析配置组合，避免网格反向依赖材料 / 边界条件。两个 crate 尚未创建，按真实功能落地，见 [领域模块规划](native-domain-boundaries.md)。

## 提交前校验

检查网格存在且有效、几何/网格修订未过期、材料覆盖目标区域、边界引用有效、参数类型与单位匹配，并核对求解器支持的单元和功能。物理上是否适定或收敛由求解器进行进一步校验，客户端预检不能代替引擎诊断。

提交时生成不可变输入快照。用户随后编辑 Study 应形成新修订，不能改变正在运行作业的含义。结果保留输入快照、协议版本和求解器版本，便于追溯。

## Python 与工作流

Python 3.12+ 是后续自动化入口，计划支持工程操作、导入、网格生成、Study 配置和作业管理。pybind11 或 Rust binding 是候选方案，选择取决于最终应用服务边界；当前没有可安装的 Python 包。

脚本调用应复用 UI 使用的应用服务、校验和任务模型，避免另建一套业务规则。批处理或无界面执行需要单独验证初始化与渲染依赖，不因存在 Python API 就宣称已支持 headless。

长期插件和工作流扩展应先稳定命令、数据及能力描述。V1 不引入 AI 功能，也不让自动化层直接访问底层库内部对象。
