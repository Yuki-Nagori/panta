# 里程碑、使用流程与验证

[架构总览](README.md)

## 当前状态

基础设施已拆分到 [任务索引](../task-index.md)，任务须先写再实施。当前完成的是文档组织，以下里程碑全部属于待实施计划。没有可运行的桌面程序，也没有实际 CI 或测试命令。先验证最容易出现集成问题的 Cargo → CMake → Qt/QML → VTK 链路，再逐步加入 CAD 与网格。

## M0：最小桌面集成

建立 Cargo 入口与 CMake native 构建，启动 QML 主窗口，通过 C++ ViewModel 完成最小命令/状态交互，显示空 VTK 视口。此阶段不接 OCCT/Netgen。

验收：干净构建和重复构建可用；运行入口正确定位程序和资源；窗口调整大小、关闭及重新打开正常；记录工具链版本、平台和图形后端。此时才能把 README 中相应构建命令改为可用。

## M1：工程与几何

实现 New/Open/Save 的基础工程模型、STEP 导入、几何显示和面/边/实体选择，连通工程树与属性面板。

验收：导入简单模型能检查单位和拓扑；失败不破坏已打开工程；保存重开后几何与 ID/引用一致；后台导入不阻塞界面。工程格式尚不完整时，在 UI 和文档标明限制。

## M2：网格闭环

接入 Netgen，产出自有 Mesh IR，提供网格参数、任务状态、质量摘要及表面/体网格显示。

验收：连接关系和边界分组正确；取消/失败保留旧网格；几何改变使旧网格及依赖配置失效；保存重开后网格与来源关系一致。

## M3：后处理与 Study

加入相机、裁剪、合成标量场、色标与基础时间步切换，完成材料分配、Study 属性编辑和持久化。提供明确标注的求解器占位状态。

验收：字段节点/单元关联、单位和色标范围正确；几何/网格选择同步；合成结果有可见标记；Study 无效引用能够定位并修正。

## M4：外部协议接入

先用 mock 求解器验证进程管理和事件流，再在外部引擎可用时联调。真实 CFD 引擎的实现与准确性验收不属于本仓库里程碑。

验收：启动、运行、取消、失败和完成路径可解释；求解器异常退出不终止 GUI；结果仅在完整发布后可读；不兼容协议有明确错误；进度流中不携带大块网格或结果数组。

## 实现后的目标使用流程

1. 新建或打开工程，确认工程位置和资产保存方式。
2. 导入 STEP，检查单位、部件结构及几何诊断。
3. 选中面/边/实体，确认属性与边界分组。
4. 设置网格参数并生成网格，检查质量和区域映射。
5. 调整视角、显示方式与裁剪；使用合成字段时确认演示标记。
6. 创建 Study，配置材料、工艺和边界条件，处理校验错误。
7. 保存工程；求解器尚未接入时止于配置保存。
8. 接入可用求解器后提交作业，查看进度并打开已发布结果。

## 验证分层

| 层次 | 验证重点 |
|---|---|
| 领域逻辑 | ID、单位、修订失效、命令与状态转换 |
| 适配器 | STEP 导入、Mesh IR 转换、VTK 数据映射 |
| 跨语言边界 | 所有权、错误映射、回调和取消生命周期 |
| 界面与渲染 | 线程交接、窗口生命周期、选择同步、资源释放 |
| 持久化 | 保存重开、损坏/缺失资产、迁移与失败恢复 |
| 求解器集成 | 协议兼容、异常退出、事件与数据发布顺序 |
| 部署 | 无开发环境机器启动、资源和动态依赖完整 |

实现模块后再添加对应自动化检查，并记录真实命令与结果。仅文档变更时检查链接、目录标注、状态描述和改动边界，不运行不存在的应用测试。
