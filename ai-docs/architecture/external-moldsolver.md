# [External / 非本仓库] MoldSolver 物理求解引擎

[架构总览](README.md)

## 归属与状态

`moldsolver` 是架构方案中独立于 panta 的求解器仓库名称。本仓库没有该引擎源码，本次也不创建或修改外部仓库。没有提供其实际地址、构建方法或发布版本，下面仅定义协作边界与建议结构。

## 引擎职责

外部引擎拥有物理模型、离散方法、矩阵装配、线性/非线性求解、时间推进、收敛控制和数值验证。FEM、FVM、DG 是可能采用的方法，不表示必须同时实现。Flow、Thermal、Filling 是预期物理方向，实际支持范围由引擎版本决定。

PETSc、hypre 是线性代数候选依赖，CPU/CUDA 是计算后端方向；它们不是 panta 的 V1 构建依赖，也不代表外部引擎已经实现 GPU 能力。

## 建议模块

| 外部路径（规划） | 责任 |
|---|---|
| `src/` | 程序入口、运行配置和引擎编排 |
| `fem/` | 若采用 FEM，管理相关离散实现 |
| `linalg/` | 矩阵、向量与求解器适配 |
| `physics/` | 流动、热传输、充填等模型 |
| `materials/` | 材料本构及物性计算 |
| `backends/` | 计算设备与执行后端 |
| `protocol/` | 协议服务端和事件发送 |
| `tests/` | 数值精度、守恒、收敛和回归验证 |

这些路径不应在 panta 下照搬建立。桌面侧仅保存材料配置与分析输入，不能因 UI 需要参数就把物理计算移入 ViewModel。

## 对接责任

引擎应声明协议版本、支持的分析类型/单元/字段及必要能力，验证 StudyRequest，发送进度与诊断，并以约定格式发布完整结果。取消、错误退出和未完成结果的语义需要双方共同约定。

引擎负责计算正确性和物理验证；panta 负责界面响应、输入引用、作业管理和结果展示。双方通过版本化协议和资产格式协作，不共享 C++ ABI 或内部对象生命周期。

关联文档：[本仓库求解器客户端](solver-integration.md)、[[External / 非本仓库] 共享协议](external-mold-protocol.md)。
