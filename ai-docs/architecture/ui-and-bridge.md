## 界面构成

目标桌面界面包含顶部菜单/工具栏、左侧工程树、中央 3D 视口、右侧属性编辑器、底部任务状态与 Console。工程树按 Geometry、Mesh、Studies、Results 组织；树选择、视口选择与属性面板应使用统一实体 ID 同步。

QML 负责布局、主题、控件和状态绑定。`CaeViewport` 是嵌入 QML 的原生渲染组件，具体渲染集成见[可视化](visualization.md)。不能让各面板直接持有或操作 OCCT、Netgen、VTK 对象。

## ViewModel 契约

`QObject` 派生 ViewModel 暴露可观察属性、命令和事件。任务 057 已注册 `ProjectViewModel`，提供工程默认目录、创建/打开/保存、重命名命令、dirty 状态和结构化错误；它只做 Qt 字符串/URL 与 Rust application service 的适配。几何导入、网格生成等长任务仍按后续 ViewModel 契约接入。

属性变化通过 NOTIFY 信号通知，错误以结构化错误加用户可读摘要呈现。长任务返回任务标识或提供可追踪的任务状态，不能仅用一个全局 busy 布尔值掩盖多个并发操作。按钮启用条件来自模型状态，例如没有有效几何时禁用网格生成。

复杂 UI 交互由 C++ ViewModel 持有的 `QStateMachine` 集中编排，首个消费者为导入窗口，见 [Qt 交互状态机设计](../modules/qt-interaction-state-machines.md) 与 [074](../task/074-qt-interaction-state-machine.md)（规划，模块尚未接入）。QML 发送意图并绑定交互状态；业务有效性、提交和取消终态仍由 Rust 决定。简单视觉状态继续使用 QML 绑定，Qt 状态机不取代 worker，也不加载 Flow `.pa`。

ViewModel 将命令交给应用服务，不负责文件解析、持久化事务或数值计算。属性编辑先验证，再提交领域命令；失败时恢复显示并解释原因，避免界面显示已经修改而工程模型未接受的状态。

## 线程与生命周期

几何导入、网格生成和大文件读取不能阻塞 UI 线程。结果通过适当的线程间通知回到对象所属线程；工作线程不能直接更新 QML 或操作视口渲染对象。

当前 `TaskHost` 在 GUI 线程拉取 Rust 任务事件并转发 Qt 信号。成功提交后启动 10ms 轮询，所有已提交任务的终态均转发后停表；停表依据是待终态任务集合，不是可能早于事件拉取归零的 `runningTasks`。终态信号处理器可同步提交后续任务，停表判断在信号转发后进行。任务服务当前仍为模拟任务入口，未接到首页业务按钮。

Qt Quick 渲染线程、GUI 线程和后台任务线程之间需要明确数据移交边界。场景更新使用快照或排队命令，并验证底层库对线程的要求。关闭工程、销毁视口或取消任务后，迟到的回调必须被任务 ID 和工程修订检查拒绝。

所有权归属需写在实现接口中：谁创建 QObject、谁释放 native 资源、任务是否持有工程快照、视口重建时哪些资源失效。跨语言对象不能靠不明确的裸指针生命周期维持。

## 交互验收

导入过程显示任务进度或不确定进度，失败后可继续操作原工程；网格任务可取消或明确显示不支持取消的阶段；选择面/边/实体时工程树与属性面板一致。错误摘要面向用户，详细诊断进入 Console/日志；不能把实现细节当作主操作流程。
