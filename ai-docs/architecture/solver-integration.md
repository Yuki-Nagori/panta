# 求解器客户端、进程与数据交换

[架构总览](README.md)

## 本仓库职责

`solver-client` 属于 chronos，负责能力检查、请求组装、外部进程生命周期、事件接收、取消、日志和结果索引。不直接链接 MoldSolver 的 C++ 库，不实现 CFD 算法。求解器进程崩溃应转为作业失败，桌面工程仍可保存和继续操作。

V1 优先考虑本地进程，未来可扩展远程或云端传输。传输方式尚未确定；IPC、gRPC、protobuf 是候选机制，不是当前已存在的依赖或协议。

## 请求与事件语义

示意 `StudyRequest` 包含 mesh、material、process、boundary_conditions、solver_options，同时需要作业 ID、输入修订、协议版本和数据资产引用。正式字段及必选条件应由共享契约定义。

计划事件包括 Started、Progress、Iteration、TimeStep、Warning、ResultAvailable、Failed、Completed。每条事件应关联作业，必要时含序号和时间信息。Iteration 可携带残差，TimeStep 可携带物理时间，Progress 可缺省数值；无可靠进度时不要伪造百分比。

客户端将事件映射为应用任务状态，界面不解析引擎内部日志来猜测结果。重复与迟到事件按当前协议的状态规则处理；未知事件按明确的协议约定拒绝或报告，不为猜测未来版本默认静默忽略。新增兼容处理必须遵循 [兼容例外规范](../standards/code-lifecycle.md)；终态一旦确认，不因迟到 Progress 回退为运行中。

## 生命周期与失败处理

建议状态为待提交、启动中、运行中、取消中以及已完成/已失败/已取消三个终态。实际枚举仍需与协议共同确定。启动失败、握手不兼容、进程异常退出、读写中断和协议解析失败分别保留原因。

启动时传递结构化参数，保存工作目录和输入快照。捕获 stdout/stderr 时明确日志与协议通道，避免任意日志破坏事件解析。取消先请求协作退出，超时后的终止策略需记录；进程退出后回收资源，并识别未完成输出。

Completed 事件和进程退出码需要一致性规则；不能仅因进程返回 0 就认定结果完整，也不能在结果尚不可读取时显示成功。长时间无事件可显示状态未知或超时诊断，自动重试计算需防止重复作业。

## 控制面与数据面

控制面只传请求、进度、残差、时间步和结果位置等元数据。大型网格和结果通过文件/Simulation DB 或后续共享内存交换，不将 GB 级数组嵌入事件流。

结果发布应先完成写入并校验，再发送 ResultAvailable，事件携带资产 ID、位置、格式版本和可选完整性信息。客户端只读取已发布数据；映射或共享内存需要明确所有者、释放时间与进程异常退出后的清理规则。

本地路径不能直接当作远程机器可访问地址。远程扩展需资产上传/下载、地址解析、认证、重连和作业恢复等单独设计，当前不承诺无改动迁移。

## 不依赖真实求解器的验证

使用 mock 进程或协议夹具覆盖正常事件、异常退出、取消、乱序/重复事件、不兼容版本、缺失结果文件和部分写入。合成结果标记为测试数据。真实物理准确性由[外部求解器](external-moldsolver.md)验证，本仓库验证集成行为。
